4การออกแบบเครือข่าย VPC และการแบ่ง Subnets VPC & Subnets

4.1 แนวคิดและการแบ่งแยกพื้นที่เครือข่าย

ใช้หลักการ Network Isolation โดยแบ่งเครือข่ายเสมือน Cloud_Project-vpc (CIDR 10.0.0.0/16) ออกเป็น 6 Subnets รองรับ 3 ชั้นการทำงานหลักกระจายตัวใน 2 Availability Zones (ap-southeast-1a และ ap-southeast-1b) เพื่อป้องกันไม่ให้เกิดความเสียหายทั่วทั้งระบบ (Blast Radius Reduction) และกำหนดช่วง IP อย่างเป็นระบบ ดังนี้

  • Public Subnets (Web Tier): 10.0.1.0/24 และ 10.0.2.0/24 — สำหรับวาง Public Load Balancer (web-lb) และเครื่อง Web Servers เพื่อรับทราฟฟิกตรงจาก Internet Gateway
  • Private Subnets (App Tier): 10.0.11.0/24 และ 10.0.12.0/24 — สำหรับวาง Internal Load Balancer (app-lb) และเครื่อง Node.js API Servers โดยออกอินเทอร์เน็ตได้ทางเดียวผ่าน NAT Gateway
  • Private/Isolated Subnets (DB Tier): 10.0.21.0/24 และ 10.0.22.0/24 — สำหรับวาง Amazon RDS PostgreSQL โดยไม่มีเส้นทางออกสู่อินเทอร์เน็ตแม้แต่น้อย (Air-Gapped)

  • DB Subnet Group: ผูกโยงกับ Subnet DB_1 (10.0.21.0/24) และ DB_2 (10.0.22.0/24) ซึ่งเป็น Isolated Subnets ที่ไม่มี Internet Gateway หรือ NAT Gateway เชื่อมโยง
  • Public Access = No: ป้องกันไม่ให้ AWS จ่าย Public IP Address ให้กับ Instance อย่างเด็ดขาด ตัดความเสี่ยงจากการสแกนพอร์ตภายนอก
  • KMS At-Rest Encryption: เข้ารหัสข้อมูลบนสตอเรจ gp3 และ Snapshot อัตโนมัติด้วยมาตรฐาน AES-256 ผ่าน AWS KMS
  • Least-Privilege Role (dns69_app): ตามสคริปต์ 003_least_privilege.sql แอปพลิเคชันเชื่อมต่อด้วย role dns69_app เท่านั้น (ห้ามใช้ Master User) สิทธิ์จำกัดเฉพาะ SELECT, INSERT, UPDATE ในตารางหลัก ตัดสิทธิ์ DROP TABLE / TRUNCATE ป้องกัน SQL Injection ทำลายระบบ และกำหนด audit_logs เป็นแบบ Append-Only (INSERT เท่านั้น)
  • DNS69 Database Schema: ประกอบด้วย 5 ตารางหลักตาม 001_schema.sql ได้แก่ faculties (6 คณะ: วิศวะ, วิทยา, แพทย์, บริหาร, นิเทศ, สถาปัตย์), app_users (แฮชรหัสผ่านด้วย bcrypt, กำหนด role: student จาก Server), matches (ตารางแข่งและเวลาปิดรับคำทาย kickoff_at), predictions (คำทาย 0–20 ประตู, ล็อกด้วยเวลา Server NOW()), และ audit_logs (บันทึกร่องรอยตรวจสอบ)
  • Free Tier Optimization (FinOps): ในสภาพแวดล้อมทดสอบจริง ได้ปรับใช้เป็น Single-AZ Deployment (บน db.t3.micro / db.t4g.micro พร้อม Storage 20 GiB และ Backup Retention 1 วัน) เพื่อให้อยู่ในกรอบโควต้า AWS Free Tier

9ระบบกระจายโหลดและเซิร์ฟเวอร์ (ALBs & AMIs) Load Balancing & AMIs

9.1 สถาปัตยกรรม Dual-ALB (Public & Internal Load Balancers)

เพื่อไม่ให้ภายนอกเข้าถึง App Tier ได้โดยตรง ระบบแยก Application Load Balancer ออกเป็น 2 ระดับ ดังนี้

  • web-lb (Public Internet-Facing ALB): รับคำขอจากผู้ใช้ภายนอกบนอินเทอร์เน็ตผ่าน DNS web-lb-1062329544.ap-southeast-1.elb.amazonaws.com กระจายโหลดไปยัง Web Tier EC2 ใน 2 Availability Zones ภายใต้ Security Group Sg-alb-public
  • app-lb (Private Internal ALB): ทำหน้าที่เป็น Internal Gateway เชื่อมระหว่าง Web Tier และ App Tier ผ่าน DNS internal-app-lb-561391200... ภายใต้ Security Group Sg-alb-internal โดย Next.js บน Web Tier ทำการ Proxy Rewrite ส่งทราฟฟิก /api/* มายัง App Tier API Engine (Port 4000) ทำให้เบราว์เซอร์ภายนอกไม่มีทางสัมผัส Backend API ได้โดยตรง

9.2 Golden Machine Images (AMIs) และระบบ Auto Scaling

ระบบสร้างภาพระบบต้นแบบ (Golden AMIs) เพื่อใช้ใน Auto Scaling Groups ทำให้สามารถขยายเซิร์ฟเวอร์ใหม่ได้ทันทีโดยไม่ต้องติดตั้งซอฟต์แวร์ซ้ำซ้อน ดังนี้

  • web-v1 (ami-0ccbb043324803789): ภาพต้นแบบของ Web Tier ติดตั้ง Nginx, Web Security Headers (CSP, X-Frame-Options: DENY, HSTS), Next.js 15 Standalone Runtime (dns69-web.service รันบน Port 3000)
  • app-v1 (ami-0dc68469ddc403945): ภาพต้นแบบของ App Tier ติดตั้ง Node.js 20 LTS, TypeScript API Engine (dns69-api.service รันบน Port 4000), Zod Schema Validation, Helmet, Rate Limiter, Pino Logger (ตัดข้อมูลลับออกจาก Log), และ SDK เชื่อมต่อ AWS Secrets Manager อัตโนมัติ

10การจัดการความลับและการรีโมต (Secrets & SSM) Secrets & SSM

10.1 Zero Hardcoded Secrets ผ่าน AWS Secrets Manager

เพื่อปฏิบัติตามมาตรฐาน OWASP Top 10 และ CIS AWS Benchmark ซอร์สโค้ดของระบบทายผลฟุตบอลกีฬาสี (DNS69 API) จะ ไม่มีการเก็บ Password, API Key หรือ JWT Secret ไว้ในไฟล์โค้ดหรือไฟล์ .env บนเซิร์ฟเวอร์โดยเด็ดขาด

  • เก็บข้อมูลสำคัญไว้ในบริการ AWS Secrets Manager (Secret ID: dns69/app / apex/prod/app) ได้แก่ DB_HOST, DB_USER (dns69_app), DB_PASSWORD, DB_NAME (dns69), และ JWT_SECRET (ความยาวอย่างน้อย 32 ตัวอักษร)
  • ตามสถาปัตยกรรมใน api/src/config.ts เครื่อง App EC2 จะเรียกใช้ loadSecrets() ผ่าน AWS SDK (@aws-sdk/client-secrets-manager) ณ เวลาเริ่มต้นโพรเซส (Runtime Retrieval) โดยใช้สิทธิ์จาก IAM Instance Profile ทำให้ไม่มีการบันทึก Long-term Access Key หรือรหัสผ่านลงดิสก์ หากโค้ดรั่วไหล ข้อมูลลับก็ยังคงปลอดภัย 100%

10.2 การบริหารจัดการเครื่องเซิร์ฟเวอร์ผ่าน AWS Systems Manager (SSM)

ระบบทายผลฟุตบอลกีฬาสีปิดพอร์ต TCP 22 (SSH) บนทุกเซิร์ฟเวอร์อย่างเด็ดขาด โดยทีมจะเข้าจัดการเครื่องผ่าน AWS Systems Manager Session Manager เท่านั้น:

  • ไม่มี Public IP และไม่ต้องเปิดพอร์ตไฟร์วอลล์: เซิร์ฟเวอร์ใน Private Subnet สามารถสื่อสารกับ SSM Endpoint ผ่าน NAT Gateway หรือ VPC Endpoint
  • เข้ารหัสผ่าน TLS 1.3: การส่งคำสั่งผ่านเบราว์เซอร์หรือ AWS CLI ได้รับการเข้ารหัสความปลอดภัยระดับสูง
  • Full Audit Trail: ทุกคำสั่งที่ผู้ดูแลระบบพิมพ์ลงใน Session Manager จะถูกบันทึกเป็นประวัติเหตุการณ์ลงใน AWS CloudTrail และ CloudWatch Logs โดยอัตโนมัติ ทำให้ตรวจสอบย้อนหลังได้ว่าใครพิมพ์คำสั่งใดเมื่อใด
หลักฐานด้าน SSM จาก AWS CloudTrail ในภาพหลักฐาน E19 (AWS CloudTrail Event History) แสดง UpdateInstanceInformation จาก Event Source ssm.amazonaws.com พิสูจน์ได้ว่าเครื่องเซิร์ฟเวอร์ในระบบเชื่อมต่อและสื่อสารผ่าน AWS Systems Manager โดยไม่ได้ใช้งาน SSH แบบดั้งเดิม

โครงงานการติดตั้ง Secure 3-Tier Web Application on AWS (ระบบทายผลฟุตบอลกีฬาสีระหว่างคณะ DNS69) ของกลุ่มที่ 2 ได้ดำเนินการติดตั้งจริงบน AWS Cloud Platform โดยการนำทฤษฎีและแนวปฏิบัติด้าน Cloud Security มาประยุกต์ใช้ในสภาพแวดล้อมคลาวด์จริงได้อย่างมีประสิทธิภาพ

การดำเนินการประกอบด้วย: การแยกเครือข่ายอย่างเคร่งครัดผ่าน 6 Subnets ใน 2 AZs, การควบคุมไฟร์วอลล์แบบ Chained Security Groups โดยปราศจากการเปิดพอร์ต SSH สู่สาธารณะ (Zero Public SSH), การบริหารตัวตนตามหลัก Separation of Duties โดยไม่มีการสร้าง Access Key ถาวร, การกระจายโหลดผ่าน Dual-ALB (web-lb และ app-lb) เชื่อมต่อ Next.js 15 Standalone และ Express API Engine, การจัดการสิทธิ์ฐานข้อมูล RDS PostgreSQL ตามหลัก Least Privilege (Role dns69_app ตัดสิทธิ์ DROP TABLE และทำ Audit Logs แบบ Append-Only), การปกป้องข้อมูลด้วยการเข้ารหัส At-Rest ผ่าน KMS, การดึงรหัสผ่านผ่าน AWS Secrets Manager แบบ Runtime และการเฝ้าระวังตลอด 24 ชั่วโมงผ่าน CloudWatch Alarms และ CloudTrail ซึ่งถือเป็นต้นแบบสถาปัตยกรรมคลาวด์ที่มีความมั่นคงปลอดภัย พร้อมรองรับการเติบโต และสอดคล้องกับมาตรฐานอุตสาหกรรมในปัจจุบัน
