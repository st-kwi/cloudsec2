1บทสรุปผู้บริหาร Executive Summary

โครงการนี้ออกแบบและติดตั้ง ระบบทายผลกีฬา (APEX PREDICT) บน Amazon Web Services (AWS) ด้วยสถาปัตยกรรม Secure 3-Tier Web Application แบ่งระบบออกเป็น Web Tier, App Tier และ DB Tier อย่างเด็ดขาด กระจายตัวข้าม 2 Availability Zones เพื่อให้ระบบพร้อมใช้งานสูง (High Availability) และยึดหลัก Cloud Security Best Practices ตามแนวทาง AWS Well-Architected Framework (Security Pillar), CIS AWS Foundations Benchmark, OWASP Top 10 และ NIST Cybersecurity Framework

แนวคิดหลักของการออกแบบคือ “ไม่ไว้ใจชั้นใดโดยปริยาย และป้องกันหลายชั้นซ้อนกัน” (Zero Trust + Defense-in-Depth) โดยคำขอจากผู้ใช้ต้องผ่านการกรองที่ AWS WAF, เข้ารหัสด้วย TLS 1.3 ที่ Application Load Balancer แล้วจึงไหลผ่าน Security Groups แบบลูกโซ่ (อ้างอิงกันด้วย SG ID ไม่ใช่ช่วง IP) ไปจนถึงฐานข้อมูลที่อยู่ใน Subnet ซึ่งไม่มีเส้นทางออกอินเทอร์เน็ตเลย ผู้ดูแลระบบบริหารเครื่องผ่าน AWS Systems Manager โดย ไม่เปิดพอร์ต SSH 22 ในทุก Security Group ข้อมูลถูกเข้ารหัสทั้งระหว่างส่งและขณะจัดเก็บด้วย AWS KMS และทุกกิจกรรมถูกบันทึกด้วย CloudTrail, VPC Flow Logs และเฝ้าระวังภัยคุกคามด้วย GuardDuty

ผลลัพธ์สำคัญ (Key Outcomes)

ด้านสิ่งที่ได้ดำเนินการ
การแบ่งชั้นเครือข่ายVPC 10.0.0.0/16 แบ่ง 6 Subnets ใน 3 ชั้น ใช้ Route Table แยก 3 ชุด — DB Tier มีเพียงเส้นทาง local (ไม่มี 0.0.0.0/0)
การควบคุมทราฟฟิกSecurity Groups 5 ชุดอ้างอิงแบบลูกโซ่ sg-alb → sg-web → sg-int-alb → sg-app → sg-db เปิดเฉพาะพอร์ตที่จำเป็น (443/80 → 80 → 5000 → 5432)
การป้องกันชั้นขอบAWS WAF (Managed Rules: Common, SQLi, Known Bad Inputs, IP Reputation + Rate-based 1,000 req/5 นาที) และ AWS Shield Standard
การเข้ารหัสTLS 1.3 (ELBSecurityPolicy-TLS13-1-2-2021-06) + HTTP→HTTPS 301, RDS/EBS เข้ารหัส AES-256 ด้วย KMS, ความลับเก็บใน Secrets Manager
ความพร้อมใช้งานALB Multi-AZ, Auto Scaling Group (min 2 / max 6) ทั้ง Web และ App, RDS PostgreSQL Multi-AZ (Synchronous Standby), Backup 7 วัน + PITR
การตรวจสอบย้อนกลับCloudTrail (Multi-Region + Log file validation), VPC Flow Logs, GuardDuty, CloudWatch Alarms → SNS Email
ความปลอดภัยแอปพลิเคชันJWT (HMAC-SHA256, หมดอายุ 8 ชม.), RBAC 3 บทบาท, Rate Limiter 3 ระดับ, Wallet Lock ป้องกัน Double Spending, Nginx Security Headers

2วัตถุประสงค์ ขอบเขต และความต้องการ Objectives & Scope

2.1 วัตถุประสงค์ (Objectives)

  1. ออกแบบสถาปัตยกรรม 3-Tier บน AWS ที่แยกส่วนนำเสนอ (Presentation) ตรรกะธุรกิจ (Business Logic) และข้อมูล (Data) ออกจากกันทั้งในระดับเครือข่ายและสิทธิ์การเข้าถึง
  2. ประยุกต์ใช้หลักการความปลอดภัยคลาวด์ (Defense-in-Depth, Least Privilege, Zero Trust, Encryption, Observability) อย่างเป็นรูปธรรมในทุกชั้น
  3. ทำให้ระบบรองรับความล้มเหลวระดับ Instance และระดับ Availability Zone ได้โดยอัตโนมัติ
  4. จัดทำคู่มือการติดตั้งทีละขั้นตอนบน AWS Management Console พร้อมเก็บหลักฐานภาพหน้าจอ 22 จุด (S01–S22) เพื่อพิสูจน์ว่าการออกแบบถูกนำไปใช้จริง

2.2 ขอบเขตของระบบ (Scope)

อยู่ในขอบเขต (In Scope)
  • VPC, Subnets, IGW, NAT Gateway, Route Tables, VPC Flow Logs
  • Public ALB + Internal ALB, Auto Scaling (Web/App), EC2 Launch Templates
  • Amazon RDS PostgreSQL Multi-AZ, KMS, Secrets Manager
  • WAF, ACM, Route 53, IAM, SSM, CloudTrail, GuardDuty, CloudWatch, SNS
  • แอปพลิเคชันทายผลกีฬา (Frontend Nginx + Node.js API)
นอกขอบเขต (Out of Scope)
  • การทำ Disaster Recovery ข้าม Region
  • ระบบชำระเงินจริง (ใช้ระบบแต้มสมมติ)
  • Infrastructure as Code / CI/CD Pipeline (เสนอเป็นงานต่อยอด)
  • CloudFront CDN และ AWS Shield Advanced

2.3 ความต้องการของระบบ (Requirements)

รหัสประเภทความต้องการตอบสนองโดย
FR-1Functionalผู้ใช้สมัคร/เข้าสู่ระบบ ดูตารางแข่ง ทายผลแบบเดี่ยวและแบบชุด (Parlay)Node.js API /api/auth, /api/bets
FR-2Functionalผู้ดูแล (Ops) จัดการคู่แข่ง อัตราต่อรอง และสรุปผลแจกแต้ม/api/matches, /api/settlement + RBAC
SR-1Securityฐานข้อมูลต้องไม่สามารถเข้าถึงได้จากอินเทอร์เน็ตIsolated Subnet + rtb-isolated-db + sg-db
SR-2Securityข้อมูลต้องเข้ารหัสทั้ง In-Transit และ At-RestACM TLS 1.3, KMS AES-256
SR-3Securityห้ามมีพอร์ตบริหารจัดการเปิดสู่สาธารณะไม่มี TCP 22 / ใช้ SSM Session Manager
SR-4Securityป้องกัน SQLi / XSS / Brute-force / FloodWAF Managed Rules + Rate Limit (Edge & App)
SR-5Securityทุกการเปลี่ยนแปลงและทราฟฟิกต้องตรวจสอบย้อนหลังได้CloudTrail, VPC Flow Logs, CloudWatch
NFR-1Availabilityทนต่อการล่มของ 1 AZ ได้Multi-AZ ALB / ASG / RDS
NFR-2Scalabilityขยายตัวอัตโนมัติเมื่อมีผู้ใช้มาก (เช่น ช่วงบิ๊กแมตช์)ASG Target Tracking CPU 75%
